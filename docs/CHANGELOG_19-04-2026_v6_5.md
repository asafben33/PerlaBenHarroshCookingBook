# CHANGELOG — גרסה 6.5 — 19/04/2026

**ספר הבישול של משפחת בן הראש ז״ל — תיקון 403 במערכת הפידבק והפחתת רעש 404 בגלריה**

---

## TL;DR

גרסה 6.4 פתרה את בעיית ה-CORS (מעבר מ-`fetch()+JSON` ל-hidden iframe + form POST). אבל בפועל FormSubmit.co דוחה את הבקשות ב-**403 Forbidden** בגלל שילוב של:

1. חסר שדה `_url` (הדפדפן לא שולח Referer מלא בגלל `strict-origin-when-cross-origin`).
2. `_captcha: false` ללא שדה זיהוי מקור חלופי — FormSubmit מחיל מגבלות אנטי-ספאם.

גרסה 6.5 מוסיפה את השדה `_url` שמציין את מקור הטופס במפורש, ומפחיתה את רעש ה-404 בקונסול (עד 66% פחות בקשות תמונות לריק).

---

## 1. רקע — למה 6.4 לא פתרה את הבעיה לגמרי?

### 1.1 שגיאת v6.4 בפועל

לאחר פריסת v6.4, הלוג בדפדפן הראה:
```
POST https://formsubmit.co/asafben33@gmail.com 403 (Forbidden)
```

ה-POST יוצא מהדפדפן (אין יותר CORS preflight), אבל FormSubmit עצמם מחזירים 403.

### 1.2 למה FormSubmit מחזירים 403?

מהתיעוד שלהם (`https://formsubmit.co/documentation`):

> **Disable reCAPTCHA `_captcha`**
> \* We highly recommend you use the reCAPTCHA (not to disable it) in order to avoid some **technical limitations which we impose from time to time** in order to filter out bots, spam, and other malicious programs.

ומ-FAQ שלהם:

> **FormSubmit emails are not showing the exact URL(with path) of my form**
> This is because many browsers have started to default to a stricter referrer policy (strict-origin-when-cross-origin) when making a cross-domain request.
> **Recommended solutions:** You can use a hidden input field with the exact form URL:
> `<input type="hidden" name="_url" value="https://yourdomain.co/contact.html">`

כלומר, הם ממליצים במפורש על השדה `_url` כשדה חובה בפריסות מודרניות.

### 1.3 למה לא נתפס ב-v6.4?

v6.4 התמקדה בפתרון ה-CORS בלבד — לא בדקה את התגובה של FormSubmit בפועל (Load event ב-iframe פשוט נורה, גם כשהתגובה היא דף שגיאה 403).

**לקח לעתיד:** יש לבדוק את קוד התגובה האמיתי של FormSubmit, לא רק את אירוע `load` של ה-iframe.

## 2. שינויים ב-v6.5

### 2.1 תיקון #1 — הוספת שדה `_url` לטופס המוסתר

**קובץ:** `index.html`, שורה 7408

**לפני:**
```html
<input type="hidden" name="_honey"       value="">
<input type="hidden" name="name"         id="fb-hf-name"         value="">
```

**אחרי:**
```html
<input type="hidden" name="_honey"       value="">
<input type="hidden" name="_url"         id="fb-hf-url"          value="">
<input type="hidden" name="name"         id="fb-hf-name"         value="">
```

### 2.2 תיקון #2 — אכלוס `_url` ב-JS

**קובץ:** `index.html`, שורה 7113 (בתוך `submitFeedback`)

**לפני:**
```javascript
setF('fb-hf-page-url',     location.href);
setF('fb-hf-user-agent',   (navigator.userAgent || '').slice(0, 200));
```

**אחרי:**
```javascript
setF('fb-hf-page-url',     location.href);
setF('fb-hf-url',          location.origin + location.pathname);
setF('fb-hf-user-agent',   (navigator.userAgent || '').slice(0, 200));
```

**הערה:** `location.origin + location.pathname` מחזיר URL נקי ללא query-string (FormSubmit דורשים URL ללא פרמטרים).

### 2.3 תיקון #3 — הפחתת רעש 404 ב-`_heroGalleryInit`

**קובץ:** `index.html`, שורות 2286–2308

**בעיה:** הקוד הישן ניסה לטעון **תמיד** שלוש תמונות עבור כל מתכון (`r-{id}.jpg`, `r-{id}-2.jpg`, `r-{id}-3.jpg`) — גם כשהוריאנטים לעולם לא קיימים. זה גרם לעשרות 404 בקונסול בכל פתיחת מתכון.

**תיקון:** כעת וריאנטים `-2` ו-`-3` מנוסים **רק אם** התמונה הראשית הצליחה להיטען. כך:
- מתכון עם תמונה ראשית + גלריה: 3 בקשות (כמו קודם).
- מתכון עם תמונה ראשית בלבד: בקשה אחת מוצלחת + 2 בקשות (-2, -3 שעלולים 404) = חיסכון 0.
- מתכון ללא תמונות כלל: בקשה אחת כושלת (4040) במקום 3. **חיסכון 66%.**

## 3. תיקונים עתידיים מומלצים (לא ב-v6.5)

### 3.1 מעבר ל-Invisible Email Endpoint (מומלץ מאוד)

FormSubmit ממליצים להחליף את `action="https://formsubmit.co/asafben33@gmail.com"` ב-hash אקראי:
`action="https://formsubmit.co/el/xyz123abc..."`.

זה:
- מונע ספאם ישיר לכתובת הגלויה (בוטים סורקים GitHub).
- מקטין את הסיכוי ל-403 הנובע מהאנטי-ספאם שלהם.
- דורש הפעלה חוזרת של הטופס (מייל אישור חדש).

**הוראות:** ראו הוראות ב-`INTEGRATION_GUIDE.md` (נוסף ב-v6.5.x).

### 3.2 מעבר ל-Web3Forms (backup plan)

אם FormSubmit ממשיכים להחזיר 403 — יש דיווחים נרחבים על downtime שלהם ב-2025-2026 — כדאי להתחיל לתכנן מעבר ל-[Web3Forms](https://web3forms.com) או [Formspree](https://formspree.io) שהם אמינים יותר. המעבר דורש רק שינוי של שדה `action` + שדה `access_key`.

## 4. בדיקת תקינות

### 4.1 אימות תיקון #1 + #2 (מייל)

1. פרסו ל-Netlify/GitHub Pages.
2. המתינו ~30 שניות.
3. פתחו חלון גלישה חדש (ללא cache).
4. לחצו על כפתור הפידבק (FAB כחול מטה-ימין).
5. מלאו הודעת בדיקה ושלחו.
6. פתחו DevTools → Network → סננו ל-`formsubmit`. חפשו את ה-POST.
7. **תגובה צפויה:** `200 OK` או `302 Found` (בהצלחה, פעם ראשונה זה 302 אל דף אימות).
8. **אם עדיין 403:** המשיכו לסעיף 3.1 (מעבר ל-Invisible Email).

### 4.2 אימות תיקון #3 (רעש 404)

1. פתחו מתכון כלשהו ללא תמונה (למשל `s2` — מרק שעועית לבנה).
2. פתחו DevTools → Console.
3. **לפני v6.5:** 3 שגיאות 404 עבור המתכון (`r-s2.jpg`, `r-s2-2.jpg`, `r-s2-3.jpg`).
4. **אחרי v6.5:** שגיאת 404 אחת בלבד (`r-s2.jpg` — הראשית). וריאנטים -2/-3 לא ננסו כלל.
