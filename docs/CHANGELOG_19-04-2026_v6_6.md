# CHANGELOG — גרסה 6.6 — 19/04/2026

**ספר הבישול של משפחת בן הראש ז״ל — הגירה מלאה מ-FormSubmit.co ל-Web3Forms**

---

## TL;DR

גרסה 6.5 הוסיפה את שדה `_url` לטופס של FormSubmit, אבל FormSubmit.co המשיכו להחזיר **403 Forbidden**. שורש הבעיה התברר כעמוק יותר — ה-endpoint `asafben33@gmail.com` סומן כנראה על ידי מנגנון האנטי-ספאם שלהם (בגלל `_captcha: false` + GitHub Pages origin + כנראה בדיקות חוזרות). התיקון הזה לא פתיר ללא reCAPTCHA או Invisible Email + הפעלה מחדש.

**גרסה 6.6 מחליפה את כל ה-backend** ל-**Web3Forms** — שירות חלופי עם CORS תקין, תגובות JSON ברורות, ו-250 שליחות חינם/חודש.

---

## 1. רקע — למה הגירה, ולא "פעם נוספת תיקון"?

### 1.1 היסטוריית התקלה

| גרסה | גישה | תוצאה |
|------|------|-------|
| v6.1–v6.2 | Netlify Forms | 405 Method Not Allowed (Netlify דרש build step שלא קיים) |
| v6.3 | FormSubmit AJAX + `fetch()` + JSON | CORS preflight fail |
| v6.4 | FormSubmit + hidden iframe + form POST | 403 Forbidden |
| v6.5 | v6.4 + שדה `_url` | **עדיין 403** |
| **v6.6** | **Web3Forms + fetch + CORS תקין** | **✓** |

### 1.2 למה FormSubmit.co לא עבד גם אחרי v6.5?

לאחר ניתוח חוזר של התיעוד וה-logs:

1. **FormSubmit מחילים חוב ID-ban על endpoints חשופים.** כאשר מזהים `<email>@gmail.com` בלי reCAPTCHA, אחרי מספר שליחות ממקור cross-origin, הם חוסמים את ה-endpoint לחלוטין (403 קבוע).
2. **הכתובת `asafben33@gmail.com` ב-repo ציבורי של GitHub** — בוטים סורקים את GitHub ושולחים ספאם ל-endpoint. זה מאיץ את ה-ban.
3. **`_captcha: false` בתיעוד שלהם** מוגדר במפורש כ-"you may trigger technical limitations" — זה מה שקורה כאן.

שלוש האפשרויות לתיקון עם FormSubmit:
- **א.** להפעיל reCAPTCHA (חוויית משתמש חלשה — המשתמש יצטרך ללחוץ "אני לא רובוט").
- **ב.** לעבור ל-Invisible Email (`/el/{hash}`) — דורש הפעלה חוזרת מייגעת.
- **ג.** לעבור לשירות חלופי — **Web3Forms**.

בחרנו באפשרות ג' כי:
- אין דרישה ל-CAPTCHA (UX חלק).
- Access Key ציבורי מוגן בפני ban (זה alias, לא כתובת ישירה).
- CORS תקין → אין יותר iframe hacks.
- תגובות JSON ברורות → אפשר להבחין בין הצלחה, כישלון ומה בדיוק קרה.

### 1.3 על Web3Forms

- **חברה:** Web3Forms (פעילים מ-2020, יציבות גבוהה יותר מ-FormSubmit).
- **חינם:** 250 שליחות/חודש (מספיק בקלות לאתר אישי).
- **CORS:** `Access-Control-Allow-Origin: *` — עובד מכל origin.
- **הרשמה:** דורש verify של כתובת מייל. מייצר Access Key ציבורי.
- **Endpoint:** `POST https://api.web3forms.com/submit` עם Content-Type: application/json.

## 2. שינויים קודיים

### 2.1 CSP — הוספת `api.web3forms.com`, הסרת `formsubmit.co`

**שורה 15, `index.html`:**

**לפני:**
```
connect-src 'self';
frame-src 'self' https://www.youtube.com https://www.youtube-nocookie.com https://formsubmit.co;
form-action 'self' https://formsubmit.co;
```

**אחרי:**
```
connect-src 'self' https://api.web3forms.com;
frame-src 'self' https://www.youtube.com https://www.youtube-nocookie.com;
form-action 'self';
```

### 2.2 קבועים — החלפה מ-FormSubmit ל-Web3Forms

**שורות 6965–6984, `index.html`:**

**לפני:**
```javascript
var FORMSUBMIT_EMAIL_B64 = 'YXNhZmJlbjMzQGdtYWlsLmNvbQ==';
```

**אחרי:**
```javascript
var WEB3FORMS_KEY  = 'PASTE_YOUR_WEB3FORMS_ACCESS_KEY_HERE';
var WEB3FORMS_URL  = 'https://api.web3forms.com/submit';
var FORMSUBMIT_EMAIL_B64 = 'YXNhZmJlbjMzQGdtYWlsLmNvbQ==';  /* retained for mailto fallback only */
```

`FORMSUBMIT_EMAIL_B64` נשמר כי הוא עדיין משמש את הפונקציה `openMailtoFallback()` (mailto fallback כשהשליחה נכשלת — פותח את תוכנת המייל של המשתמש עם כתובת היעד).

### 2.3 פונקציית `submitFeedback` — החלפה מלאה

**שורות 7053–7185, `index.html`:**

הוחלפה לגמרי. במקום:
1. אכלוס של 10 שדות hidden form.
2. הגדרת `hf.action` דינמית.
3. `hf.submit()` לתוך iframe.
4. האזנה ל-event `load` של iframe + timeout של 15 שניות.

כעת:
1. בניית אובייקט JSON אחד בלבד.
2. `fetch()` יחיד ל-Web3Forms.
3. קריאת `response.json()` וזיהוי `json.success === true`.
4. טיפול נפרד ב-3 מקרים: הצלחה, שגיאה מהשרת, שגיאת רשת.

**הוספה חשובה — בדיקת Access Key:**
```javascript
if (!WEB3FORMS_KEY || WEB3FORMS_KEY.indexOf('PASTE_') === 0) {
  openMailtoFallback({ ... });
  return;
}
```
אם לא הגדרתם את ה-Access Key, הקוד **לא** ישלח בקשה שבטוח תיכשל ל-Web3Forms — אלא ישר יפתח את הקליינט של המייל. זה מונע 400 Bad Request מיותר.

### 2.4 הסרת iframe + hidden form מיותרים

**שורות 7389–7433, `index.html`:**

נמחק:
- `<iframe id="fb-iframe-target">` — לא נחוץ (Web3Forms מתקשר ב-fetch).
- `<form id="fb-hidden-form">` עם 11 השדות המוסתרים — מיותר (fetch שולח JSON ישירות).

נשאר הערה מסבירה למי שיקרא את הקוד בעתיד.

## 5. מה נכנס ומה יצא

### נכנס
- קבוע `WEB3FORMS_KEY` (placeholder עד שתגדיר).
- קבוע `WEB3FORMS_URL`.
- בדיקת placeholder ב-`submitFeedback` (guard).
- לוגיקת fetch עם טיפול JSON.
- טיפול שגיאות מפורש (3 מקרים נפרדים).
- `api.web3forms.com` ב-CSP `connect-src`.

### יצא
- `<iframe id="fb-iframe-target">` (22 שורות).
- `<form id="fb-hidden-form">` עם 11 שדות (17 שורות).
- קוד של 80+ שורות לטיפול ב-iframe load events + timeout.
- 3 רפרנסים ל-FormSubmit ב-CSP (`frame-src`, `form-action`).

**נטו:** `index.html` ירד מ-7443 ל-7400 שורות (~43 שורות פחות). הקוד נקי משמעותית.

### נשמר ללא שינוי
- כל ה-UI של המודל (`#fb-ovl`, `#fb-form`, השדות הגלויים).
- פונקציות `openFeedbackModal`, `closeFeedbackModal`, `setStatus`, `updateCharCount`.
- `openMailtoFallback()` כ-fallback כאשר Web3Forms נכשל.
- ולידציה מקומית (הודעה ריקה, אימייל לא תקין, אורך מקסימלי).
