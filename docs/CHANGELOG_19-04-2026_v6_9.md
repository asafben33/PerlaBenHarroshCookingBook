# CHANGELOG — גרסה 6.9 — 19/04/2026

**ספר הבישול של משפחת בן הראש ז״ל — הפעלת PWA Install + שיפור Back-to-Top**

---

## TL;DR

דו"ח אבחון של v6.8 הראה ששני הרכיבים שהוגדרו כ-"כבר קיימים" במציאות **לא פעלו כצפוי** עבור המשתמש הרגיל:

1. **PWA Install** היה מוסתר כברירת מחדל (`style="display:none"`), ומוצג רק כש-Chrome/Edge מחליטים לפי ה-engagement heuristic שלהם שהאתר "ראוי להתקנה". משתמשים רבים **לעולם לא רואים את האירוע הזה** ולכן לא רואים את הכפתור.
2. **Back-to-Top** היה קטן (42px), שקוף (0.8 ב-`.on`), וסף הגלילה שלו היה 450px — נראה מאוחר מדי.

גרסה 6.9 מתקנת את שני הדברים ישירות, בלי לחכות ל-"heuristic" של דפדפנים.

## 1. PWA Install Button — תיקון ארכיטקטוני

### הבעיה המדויקת

ב-v6.3, הקוד נבנה עם ההנחה: "הכפתור יהיה מוסתר עד ש-Chrome ידווח שהאתר ניתן להתקנה". בפועל, ה-heuristic של Chrome דורש:
- המשתמש ביקר באתר **לפחות פעמיים** במרחק של 5+ דקות.
- האתר עמד בכל דרישות PWA מלאות (manifest, SW, icons).
- הדפדפן זיהה "אינטראקציה משמעותית" (גלילה, קליקים).

מי שמבקר באתר פעם ראשונה → **הכפתור לא מופיע אף פעם**. גם אחרי 10 ביקורים, ייתכן ש-Chrome לא יחליט להפעיל `beforeinstallprompt`.

זה היה "present but invisible" — אשליה שהכפתור קיים.

### התיקון

**שינוי #1:** הוסרה `style="display:none"` מה-HTML. הכפתור גלוי כברירת מחדל.

```html
<!-- לפני -->
<button id="pwa-install-btn" class="hdr-btn hdr-btn-install"
        ...
        style="display:none">

<!-- אחרי -->
<button id="pwa-install-btn" class="hdr-btn hdr-btn-install"
        ...>
```

**שינוי #2:** ה-JS שוחזר. עכשיו הוא רק **מסתיר** את הכפתור ב-3 מקרים מוגדרים, במקום "מראה כש-X":

```javascript
// הסתרה במקרים:
// 1. רץ במצב standalone (המשתמש כבר התקין)
// 2. המשתמש דחה בעבר (SEEN_KEY ב-localStorage)
// 3. אירוע appinstalled נורה
```

**שינוי #3:** לחיצה על הכפתור מטפלת ב-5 מסלולים מותאמים לדפדפן:
- **Chrome/Edge/Brave desktop/Android** — משתמש ב-native prompt אם זמין, אחרת מציג הוראות על אייקון ההתקנה בסרגל הכתובת.
- **iOS Safari** — הוראות "הוסף למסך הבית" דרך Share button.
- **Android** — הוראות "התקן אפליקציה" דרך תפריט הדפדפן.
- **Firefox desktop** — הסבר שאינו תומך בהתקנה + הצעת bookmark.
- **Safari macOS** — הוראות "הוסף ל-Dock".

### היתרון

אפילו משתמש שרק פעם אחת מבקר באתר ולוחץ על "התקן" — יקבל הוראות מותאמות לדפדפן שלו ויוכל להתקין ידנית. אין יותר תלות ב-Chrome heuristic.

### מה אם ה-prompt הטבעי קיים?

הקוד עדיין קולט את `beforeinstallprompt` כשהוא נורה, ואז לחיצה על הכפתור מפעילה אותו ישירות (native flow — שקוף ונעים מאוד). זה לא בוטל.

## 2. Back-to-Top — שיפורים חזותיים ופונקציונליים

### הבעיה

- **גודל:** 42×42px — קצת קטן מדי לטאצ' או להבחנה.
- **אופסיטי:** `opacity: .8` כשמופיע — נראה "חצי שקוף", לא מושך עין.
- **סף גלילה:** 450px — באתר עם גלילה ארוכה, המשתמש כבר רחוק למטה לפני שהכפתור מופיע.
- **אנימציית כניסה:** fade בלבד, בלי תנועה — קצת שטוח.
- **בדיקה אחת בלבד:** הכפתור נבדק רק באירוע `scroll`. אם משתמש נכנס לדף דרך קישור עמוק (anchor) או דרך bfcache — הכפתור לא מוצג עד שהוא גולל פעם אחת.

### התיקון

```css
/* v6.9 */
#back-top {
  width: 48px; height: 48px;                    /* +14% מ-42px */
  background: var(--c-gold);
  border: 2px solid rgba(255,255,255,.15);      /* מסגרת עדינה ל-contrast */
  font-size: 1.3rem; font-weight: 700;
  opacity: 0; transform: translateY(12px) scale(.85);  /* נכנס מלמטה */
  transition: opacity .28s, transform .28s, background .15s;
  box-shadow: 0 6px 20px rgba(20,8,2,.28), 0 2px 4px rgba(20,8,2,.18);
  pointer-events: none;                         /* אינו חוסם קליקים כשמוסתר */
}
#back-top.on { opacity: 1; transform: translateY(0) scale(1); pointer-events: auto; }
#back-top:hover { background: var(--c-gold-l); transform: translateY(-3px) scale(1.05); }
#back-top:focus-visible { outline: 2px solid var(--c-gold-l); outline-offset: 3px; }

@media (max-width: 480px) {
  #back-top { width: 44px; height: 44px; bottom: 1rem; left: 1rem; font-size: 1.15rem; }
}
```

```javascript
// v6.9 — JS changes
var _updateBackTop = function() {
  backTop.classList.toggle('on', window.scrollY > 300);  // היה 450
};
window.addEventListener('scroll', _updateBackTop, { passive: true });
_updateBackTop();  // בדיקה אוטומטית בטעינה (חשוב ל-bfcache)
```

### רשימת שיפורים

| אלמנט | לפני | אחרי |
|-------|------|------|
| גודל | 42×42px | 48×48px desktop, 44×44px מובייל |
| אופסיטי ב-`.on` | 0.8 | 1.0 |
| כניסה | fade בלבד | fade + translate + scale (אנימציית pop) |
| הובר | opacity → 1 | background change + scale 1.05 + lift 3px |
| סף גלילה | 450px | 300px |
| בדיקה בטעינה | ✗ | ✓ |
| focus-visible | ✗ | ✓ outline |
| Border | ללא | `2px solid rgba(255,255,255,.15)` |
| Shadow | קטן | כפול (`0 6px 20px` + `0 2px 4px`) |

## 3. בדיקה לאחר פריסה

### PWA Install
1. פתח את האתר בחלון incognito (חייב — cache ישן יצור בלבול).
2. **הכפתור "התקן" חייב להיות נראה בכותרת, מימין לכפתור EN**, עם אנימציית pulse עדינה.
3. לחץ עליו:
   - ב-Chrome/Edge שאפשרי ל-native prompt → יופיע דיאלוג התקנה של הדפדפן.
   - אחרת → יופיע dialog עם הוראות מותאמות לדפדפן.
4. אם אישרת התקנה — הכפתור ייעלם ולא יופיע יותר (עד שתסיר את האפליקציה).

### Back-to-Top
1. פתח את העמוד הראשי.
2. גלול מטה כ-300px.
3. **כפתור עגול זהוב עם חץ למעלה (↑) חייב להופיע בפינה שמאלית-תחתונה** עם אנימציית pop קלה.
4. הובר עליו → יתרומם מעט ויהפוך לזהב-בהיר.
5. לחץ → גלילה חלקה לראש העמוד.

## 6. הערה על התיעוד הקודם

ב-v6.8 כתבתי: "Install as App — Task 2 לא נדרש, כבר קיים ועובד". זה היה **טעות בניסוח** — הקוד קיים, אבל הוא לא עבד בפועל בגלל תלות ב-heuristic של Chrome. זו דוגמה למה שלפעמים "קיים בקוד" ≠ "עובד בפועל". התנצלות וזה תוקן כאן ב-v6.9.

אותו דבר עבור Back-to-Top — היה טכנית "קיים", אבל קטן, שקוף, וסף גלילה גבוה גרמו לו להיות כמעט בלתי-מורגש. התיקון כאן משפר את ה-UX משמעותית.
