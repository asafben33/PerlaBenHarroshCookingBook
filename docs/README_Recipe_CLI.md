# Recipe CLI — ספר הבישול של פרלה ז"ל

שני סקריפטי Python אינטראקטיביים לניהול מתכונים ב-`data.js` בלי לערוך קוד JavaScript ידנית.

---

## מבנה הקבצים

| קובץ | תפקיד |
|------|-------|
| `recipe_utils.py` | ספריית עזר משותפת (פרסר, כותב, לוגר, ממשק CLI). חובה להניח באותה תיקייה עם שני הסקריפטים. |
| `add_recipe.py` | אשף הוספת מתכון חדש. |
| `edit_recipe.py` | אשף עריכה/מחיקה של מתכון קיים. |

**דרישות מקדימות:** רק Python 3.7+ מותקן. אפס ספריות חיצוניות.

---

## התקנה

1. הורד את שלושת הקבצים (`recipe_utils.py`, `add_recipe.py`, `edit_recipe.py`).
2. הנח את שלושתם **באותה תיקייה כמו `data.js`** (תיקיית השורש של הפרויקט).
3. בדוק שהפייתון עובד:
   ```powershell
   python --version
   ```
   צריך להציג `Python 3.7.x` או גבוה יותר.

## שימוש בסיסי

### הוספת מתכון חדש

```powershell
python add_recipe.py
```

האשף ישאל אותך שאלה אחר שאלה:
1. **קטגוריה** (מרקים / סלטים / תבשילי ירקות / ...). הצג מספר לבחירה.
2. **מזהה (ID)** — הסקריפט מציע אוטומטית את ה-ID הבא בקטגוריה. לחץ Enter לאישור או הקלד אחר.
3. **כותרת, תיאור, זמן, מנות, קושי, תמונה** — שדות סטנדרטיים.
4. **תמונה** — אם משאירים ריק, יוקצה placeholder של `picsum.photos` (אפשר להחליף מאוחר יותר עם `download_images.py`).
5. **זיכרון / סיפור מרוקו** — חובה בכל מתכון.
6. **מרכיבים** — אחד אחרי השני. כדי לסיים, השאר כמות ריקה.
7. **שלבי הכנה** — כל שלב כולל זמן ("5 דק׳") וטקסט הוראה.
8. **טיפ סופי** — אופציונלי.

בסוף תראה **תצוגה מקדימה** ותתבקש לאשר. לחץ `כ` לאישור / `ל` לביטול.

### עריכת מתכון קיים

```powershell
python edit_recipe.py
```

1. **חיפוש** — הקלד ID מדויק (למשל `s1`) או קטע מהכותרת (למשל `חרירה`).
2. אם נמצאו כמה תוצאות — בחר אחת.
3. **פעולה** — ערוך / מחק / בטל.
4. אם עריכה — הסקריפט עובר שדה אחר שדה:
   - **Enter** = השאר כמו שהיה.
   - **טקסט חדש** = החלף.
   - **`-`** (מקף בודד) = נקה שדה אופציונלי.
5. עבור מרכיבים/שלבים — תפריט פעולות: `ה`=הוסף, `ע`=ערוך, `מ`=מחק, `ס`=סיום.
6. תצוגה מקדימה → אישור → שמירה.

## מצב Dry-Run (תצוגה בלבד, ללא שינוי הקובץ)

שני הסקריפטים תומכים ב-`--dry-run` (או `-n`):

```powershell
python add_recipe.py --dry-run
python edit_recipe.py -n
```

במצב זה:
- כל התהליך אינטראקטיבי רץ כרגיל.
- בסוף, הפלט נכתב לקובץ בשם `data.js.dryrun` **במקום** לדרוס את `data.js`.
- כך אפשר לבדוק את הפלט לפני שמחליטים להחיל אותו באמת.

## תהליך עבודה מומלץ (Best Practice)

### הוספת מתכון

```powershell
# 1. Dry-run ראשון כדי לוודא שהכל תקין
python add_recipe.py --dry-run

# 2. בדוק את data.js.dryrun בעורך טקסט — ודא שהמתכון נראה טוב
code data.js.dryrun

# 3. אם מרוצה, רוץ באמת
python add_recipe.py

# 4. בדוק באתר שהמתכון מופיע כראוי
# (פתח index.html מקומית או חכה לפריסת Netlify)

# 5. אם הכל בסדר, דחוף לגיט
git add data.js
git commit -m "Add recipe: מרק סלק של סבתא"
git push origin main
```

### עריכת מתכון

```powershell
# 1. Dry-run
python edit_recipe.py --dry-run

# 2. רוץ באמת
python edit_recipe.py

# 3. בדוק → commit → push
```

## טיפול בשגיאות נפוצות

| שגיאה | משמעות | פתרון |
|-------|--------|-------|
| `data.js not found` | הסקריפט לא בתיקייה הנכונה | `cd` לתיקייה שמכילה את `data.js`, או השתמש ב-`--data` |
| `מזהה 's1' כבר קיים` | ניסית להוסיף ID שקיים | השתמש ב-ID אחר (הסקריפט מציע אוטומטית) |
| `כותרת כבר קיימת` | יש מתכון עם אותה כותרת | אשר שברצונך להמשיך בכל זאת, או שנה כותרת |
| `Recipe ID '...' not found` | ה-ID שהזנת לעריכה לא קיים | חפש לפי כותרת במקום |
| שגיאת Python | ראה את `logs/` ללוג המלא | שלח לי את הלוג ואטפל |

## מה הסקריפטים **לא** עושים

- **לא** מורידים תמונות (זה תפקידו של `download_images.py`).
- **לא** דוחפים לגיט (צריך לעשות ידנית — כך יש לך שליטה על ה-commit message).
- **לא** מאמתים URL של תמונות/וידאו (הם רק נשמרים כטקסט).
- **לא** בודקים יחידות מידה או כמויות ("2 גרם" ו"2 ק"ג" נראים אותו דבר לסקריפט).
- **לא** משנים את `const CATS` (הוספת קטגוריה חדשה דורשת עריכה ידנית — אם תצטרך, אעזור).

## תמיכה ב-RTL (עברית) ב-Windows

**בעיה מוכרת:** Windows Terminal, PowerShell, ו-CMD לא מיישמים כראוי את Unicode Bidirectional Algorithm (BiDi) עבור פלט של תוכניות Python. התוצאה: עברית מופיעה הפוכה בטרמינל (כל מילה נקראת מסוף להתחלה).

**הפתרון בסקריפטים:** הסקריפטים מזהים אוטומטית שהם רצים על Windows ומפעילים מנגנון `rtl_fix` — הם הופכים מראש כל רצף עברי לפני הדפסה, כך שכאשר הטרמינל מצייר את התווים משמאל לימין (ללא BiDi), הקריאה מימין לשמאל תניב את הטקסט המקורי בצורה תקינה.

**הפעלה/כיבוי:**
- **Windows** (ברירת מחדל): `rtl_fix` מופעל אוטומטית. ההצגה בעברית תהיה קריאה.
- **Linux/macOS** (ברירת מחדל): `rtl_fix` כבוי. הטרמינלים שם מיישמים BiDi תקין.
- **כיבוי ידני** (אם יום יבוא ו-Windows יתוקן, או אם אתה משתמש בטרמינל Windows מודרני שתומך BiDi):
  ```powershell
  python add_recipe.py --no-rtl-fix
  python edit_recipe.py --no-rtl-fix
  ```

**הערה:** גם ב-Windows, ה-echo של הטקסט שאתה מקליד (לדוגמה כאשר אתה עונה על שאלה) מוצג ע"י הטרמינל, לא ע"י הסקריפט. לכן הקלדה בעברית עשויה להראות תקינה (ה-Win32 API מיישם BiDi עבור קלט), ואחרי אישור ההזנה הסקריפט יראה את הטקסט בצורה הלוגית הנכונה.
